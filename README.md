# agy 的 1M 窗口，为什么到 256K 就开始丢历史

这是 [公众号 340-A](https://github.com/lmxxf/ai-theorys-study/blob/main/wechat/340-A.md) 的简化记录，也是本目录补丁的来由。

2026 年 10 月，Antigravity CLI（`agy`）支持了 Gemini 4 Argon。选中 Argon Low 后，`/context` 面板显示 **1.0M tokens**。可真拿它读长文档，上下文刚过25万，数字就开始倒退：255,921 → 247,567 → 241,167。关掉自动 checkpoint 也没用，早先的对话仍然被裁掉。

我们查了本地 SQLite 会话数据库。真实请求的 `max_context_tokens` 写着 **256000**，而不是面板上的1M。这里发生的是发送前裁剪历史，并没有生成摘要；所以关闭自动总结解决不了问题。

## 为什么改一次还不行

最初尝试改二进制里的256000常量和内嵌模型配置，但新请求落盘仍然是256000。继续追配置加载过程才发现：前面的设置还会被后续的特征配置覆盖。

最后把修改放在**配置合并完成、即将写回运行配置的出口**：只对 Argon Low，把最终窗口预算设为1000000。这样后面的请求才真正用上更大的窗口。

与此同时，项目里的 `AGENTS.md` 也出了问题。文件约119KB，客户端原本只读前24000字节；把文件读取上限放大后，模型反而连开头都没收到。

原因是还有第二层限制：**规则与自定义内容各有20000 tokens的总预算**。半截文件能塞进去，完整文件却超了预算。客户端对超预算规则的处理是整份排除，只留下“需要时查看文件”的提示。

所以两层都要改：单文件读取上限提高到1MiB，两项总预算各提高到131072 tokens。

## 最后怎么改的

本机是 Linux ARM64，`agy` 是 Go 编译的二进制。我们保持文件长度不变，在最终配置出口插入跳转；把自动 checkpoint 的判断函数改为直接返回，再借用它不再执行的函数体放置补丁代码。

这里还踩过一次返回值的坑：那个函数返回的是 `(bool, error)`。只把布尔值清零，残留的寄存器会被调用方当成错误对象，导致崩溃。修正为返回 `false, nil` 后，请求恢复正常。

这些修改针对本地客户端的上下文处理，没有修改模型权重。自动 checkpoint 关闭后，请求仍受模型窗口上限约束。

## 验证结果与后续

**1.3.5 的验证分了三步：**

- 新请求数据库中的实际上限变为 **983040 tokens**，即1048576减去65536的输出预留。
- `user_rules` 保存了119283字节，其中逐字包含本地 `AGENTS.md` 全部118908字节，不再出现预算排除提示。
- 连续读取30篇长文后，上下文达到 **474.8K tokens**，跨过了原来的256K限制，早期内容仍保留。

10月17日，客户端自动升级到 **1.4.0**，旧补丁被覆盖。新版函数位置已经变化，不能继续使用旧偏移。重新定位、核对指令后补回上述修改，新会话正常返回，数据库再次确认983040的实际上限和完整规则注入。**1.4.0目前完成了小请求验证，未重跑超过256K的长会话测试。**

这次排查留下的经验很直接：面板显示的是一个数字，实际请求用的是另一套配置。是否修好，要看发出去的请求和落盘内容。
